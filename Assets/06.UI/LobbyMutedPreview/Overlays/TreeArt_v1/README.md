# 특성 트리 아트 리소스 v1

승인된 4방향 특성 트리를 바탕으로 만든 분리형 아트 세트입니다. 아이콘, 테두리, 마법진은 실제 알파 채널이 있는 PNG이며, 이름·수치·연결선은 개별 스프라이트에 굽지 않았습니다.

## 구성

| 분류 | 수량 | 용도 |
| --- | ---: | --- |
| 중앙 마왕 아이콘 | 1 | 중앙 노드. 화면에 `마왕` 문구를 붙이지 않음 |
| 계열 상징 | 4 | 마왕군 조련·인간계 저주·주문 연구·지배의 지혜. 테두리 없이 사용 |
| 일반 특성 아이콘 | 36 | 계열당 3경로 × 3단계 |
| 특화 특성 아이콘 | 4 | 계열별 마지막 특성 |
| 일반 테두리 | 4 | 계열별 색상 |
| 특화 테두리 | 4 | 계열별 색상, 일반보다 장식이 큰 이중 테두리 |
| 중앙 테두리 | 1 | 붉은 중앙 마왕 노드 |
| 마법진 | 1 | 투명 배경의 저채도 가넷색 장식 |

총 55개 개별 스프라이트와 7개 시트를 제공합니다. 개별 PNG와 시트는 같은 그림의 대체 사용 방식입니다. 실제 구현에서는 둘 중 하나를 선택해 중복 참조를 피합니다.

## 폴더

- `Sprites/Icons/`: 테두리·텍스트 없는 아이콘 45개. 각각 256 × 256.
- `Sprites/Frames/`: 독립 테두리 9개. 각각 256 × 256.
- `Sprites/Decor/MagicCircle_Garnet.png`: 1024 × 1024 마법진.
- `Sheets/Icons_All_45.png`: 9열 × 5행 아이콘 모음, 2304 × 1280.
- `Sheets/Icons_Core.png`: 중앙 마왕과 계열 상징 5개.
- `Sheets/Icons_Legion.png`, `Icons_Curse.png`, `Icons_Spells.png`, `Icons_Wisdom.png`: 계열별 5열 × 2행.
- `Sheets/Frames_All_9.png`: 3열 × 3행 테두리 모음.
- `Preview/`: 확인용 어두운 배경을 넣은 합성 이미지. 실제 UI 리소스로 사용하지 않습니다.
- `Reference/Tree_Layout_Transparent.png`: 신규 리소스로 다시 조합한 전체 트리 배치 참고 이미지. 원본 래스터의 단순 배경 제거본이나 실제 게임 UI 구현 결과가 아닙니다.
- `Source/`: 생성 원본 보존. 크로마 배경·체크무늬가 포함된 작업 자료이며 실제 UI에는 사용하지 않습니다.
- `AssetMap.json`: 파일명, 한글 이름, 계열, 단계, 시트 좌표 대응표.
- `Validation.json`: 알파 채널, 투명 픽셀, 크로마 잔색 검사 결과.
- `GENERATION.md`: 생성 프롬프트와 후처리 기록.

## Unity 조합 방법

뒤에서 앞으로 `마법진 → 연결선 → 테두리 → 아이콘 → 텍스트` 순서로 배치합니다.

1. 일반/특화 노드는 `Frame`과 `Icon`을 각각 별도 `Image`로 두고 같은 중앙 앵커와 피벗을 사용합니다. 두 PNG 모두 동일한 256 사각 캔버스에 맞춰져 있으므로 같은 Rect 크기에서 겹칠 수 있습니다.
2. 일반 특성에는 `Frame_Normal_*`, 마지막 특화 특성에는 `Frame_Specialized_*`를 사용합니다. 중앙 마왕에는 `Frame_Central_DemonKing`을 사용합니다.
3. 계열 이름에 해당하는 `Icon_Header_*`에는 테두리를 추가하지 않습니다. 이름은 별도 TMP 텍스트로 둡니다.
4. `Image` 색상은 흰색으로 시작합니다. 이미 계열 색상이 들어 있어 추가 틴트는 색을 바꿉니다. `Preserve Aspect`를 켜고 가로세로를 다르게 늘리지 않습니다.
5. 마법진은 트리 뒤에 두고 알파 약 0.22부터 조절합니다. 화면 전체 배경은 포함하지 않았습니다.
6. 클릭은 노드의 Button에서 처리하고, 장식용 아이콘·마법진에는 `Raycast Target`을 끕니다. 연결선·이름·레벨/잠금 상태는 추후 구현 범위입니다.

## 적용된 임포트 설정

- 개별 PNG 55개: `Sprite (2D and UI)` / `Single`.
- 시트 7개: `Sprite (2D and UI)` / `Multiple`, 256 셀 기준 이름별 분할 완료.
- 시트별 실제 로드 수: 전체 아이콘 45, Core 5, 계열별 각 10, 테두리 9. 총 99개 하위 스프라이트.
- `Filter Mode: Point`, `Compression: None`, `Generate Mip Maps: Off`, `Wrap Mode: Clamp`.
- `Alpha Source: Input`, `Alpha Is Transparency: On`, `Mesh Type: Full Rect`, `Pixels Per Unit: 100`, 중앙 피벗.
- Unity Sprite Editor 데이터 공급자를 통해 임포트했습니다. `.meta`를 직접 편집하지 않았습니다.

## 검증 및 범위

- 55개 개별 PNG의 실제 알파와 투명 영역 검사 완료. 검사 기준의 크로마 녹색 잔색 0.
- 합성 샘플과 전체 트리 미리보기의 아이콘·테두리 겹침 및 텍스트 배치 확인.
- Unity에서 개별 스프라이트와 시트 분할 결과를 확인했고, 작업 후 Console 오류/경고 조회 결과 0개.
- `UI_Lobby_MutedPreview.unity`, 기존 오버레이 Prefab, ProjectSettings, Packages는 수정하지 않았습니다.
- 이번 작업은 아트 생성 및 임포트만 포함합니다. 프리팹 배치·게임 데이터 연결·Play Mode 상호작용 검증은 아직 하지 않았습니다.
- 추후 배치 시에는 실제 UI 크기에서 픽셀 가독성, 아이콘 겹침, 클릭 영역, 확대/이동 동작을 확인해야 합니다. 물리·Animator·Input System 설정 변경은 없습니다.

## 재생성 / Git 검토

프로젝트의 `Tools/Art/BuildTraitTreeArt.cjs`는 보존 원본에서 알파 처리, 분리, 정렬, 시트 합성, 미리보기와 검사 파일을 재생성합니다. Node.js와 `sharp`가 필요하며 이미지 생성 API를 다시 호출하지 않습니다. 기존 PNG를 다시 생성하더라도 `.meta`는 유지해야 합니다.

Git 검토 대상은 신규 `TreeArt_v1` 폴더와 Unity가 생성한 `.meta`, 후처리 도구입니다. 기존 씬/프리팹/외부 원본 변경을 포함하지 마세요. 이미지 사용 방식이 확정되면 `Source`, `Preview`, 중복 시트의 프로젝트 내 보존 위치는 별도 정리 작업으로 판단할 수 있습니다.
