# 난이도별 용사 천막 (#81)

## 적용 범위

`InGame`의 흙갈래 진입로를 제거하고 주변 잔디를 그대로 노출한다. 마왕군의 확장 흙 타일과 유닛 스폰 수·위치·전투 규칙은 유지한다.

`OutdoorBattlefieldConfigSO`가 공통 장식과 천막 배치를 분리한다. `OutdoorBattlefieldStageBinding`은 Bootstrap의 확정된 `SelectedStageId`와 `Changed` 알림을 받아 화면에 전달한다. 씬 진입 요청을 추가로 소비하지 않는다.

| 스테이지 ID | 천막 수 |
| --- | --- |
| `stage_normal_30`, `bal_normal_30`, `stage_dummy_normal` | 1 |
| `stage_hard_50`, `bal_hard_50`, `stage_dummy_hard` | 3 |
| `bal_hell_100` | 5 |

미지정 스테이지는 기본 1개다. 후속 승인에 따라 기존 `StageBalHell100.asset`을 공용 `StageCatalog.asset`에 등록했다. StageChoice에서 보통 30 / 어려움 50 / 헬 100라운드를 선택할 수 있다. 헬의 기존 ID와 스폰·보상 데이터는 그대로 재사용하며, 별도 밸런스 수치를 만들지 않는다.

## Inspector 설정

`Assets/_Project/Data/InGame/OutdoorBattlefieldConfig.asset`:

- Camp Tent: 기존 천막 스프라이트와 기준 위치.
- Camp Props: 중앙 천막의 상자·통. 천막과 함께 위로 이동한다.
- Camp Layouts: 스테이지 ID와 천막 수. 중앙 기준 대칭이므로 수는 양의 홀수다.
- Camp Vertical Offset: 현재 1.5칸. 중앙 천막 y=8.6 → 10.1.
- Tent Spacing: 현재 4.5칸. 중앙 x=3.5를 유지하고 양쪽에 추가한다.
- Approach Tiles: 비워 두어 진입로를 생성하지 않는다. 기존 원본 리소스는 삭제하지 않았다.

같은 설정을 반복 전달하면 캠프를 재생성하지 않는다. 비활성화 시 기존 루트를 제거하고 재활성화 시 선택된 배치를 다시 만든다. 배치 그리드 내부를 덮는 장식은 기존 보호 규칙에 따라 표시하지 않는다.

높아진 천막이 상단 HUD에 가려지지 않도록 `InGame`에만 `OutdoorBattlefieldCameraConfig.asset`을 연결했다. 공용 설정을 복사해 전투 여백만 4 → 5로 조정했으며 준비 화면 설정은 동일하다. 다른 씬의 카메라 설정은 유지한다.

## 검증 및 제한

- 실제 InGame 준비 화면에서 진입로 0개, 잔디와 확장 영역 유지 확인.
- 보통 런에서 1개, 기존 어려움 데이터로 시작한 테스트 런에서 3개 연결 확인. 어려움은 로비 클릭 대신 런타임 테스트 주입으로 선택했다.
- 최초 헬 배치 검증은 배경 ID만 교체한 미리보기였다. 후속 검증에서는 실제 StageChoice Controller의 선택 진입점을 호출해 헬 준비 → 전투 → 패배 → 재도전을 확인했다. 재도전 후에도 헬 100라운드와 천막 5개가 유지된다. 100라운드 전체 완주는 검증하지 않았다.
- 1/3/5 및 미지정 기본값, 반복 설정과 재활성화 시 단일 캠프 루트 확인.
- 보통 첫 전투 후 기존 웨이브 결과 표시 확인. 코어루프·그리드·최종 결과 자동 검증 재실행.
- 검증 후 Play Mode 종료, XP/레벨/LP 저장값과 백그라운드 실행 설정 복구.

좌측 웨이브 패널은 토글로 숨길 수 있으므로 사용자 결정에 따라 천막 배치를 추가 조정하지 않는다.

메뉴 겹침의 원인은 `InGame`에 저장된 `Popup_Menu_Lobby`의 초기 활성 상태였다. 해당 씬 인스턴스만 비활성으로 저장했다. 공용 프리팹이나 메뉴 코드는 변경하지 않았다. 준비/전투 중 메뉴 버튼 열기, 설정 이동, 뒤로 가기, 닫기 및 재도전 후 초기 상태를 확인했다.

StageSelectionSetup도 3개 스테이지를 등록하도록 갱신하여 설정 재실행으로 헬이 누락되지 않게 했다. StageSelectionVerification(30/50/100라운드, 전체 풀 호환성, 진입 전달/재도전 데이터) 및 RunResultVerification 통과. Console 오류 0개. 기존 결과 UI의 한글 폰트 글리프 경고는 남아 있다.

`InGame_2`와 `InGame_UIIntegration` 통합, 마왕 캐릭터 연결, 별도 로비 UI의 난이도 매핑 변경, 기존 더미 UI 교체, 폰트 수정, 비 16:9 화면 및 실행 빌드 검증은 이번 범위 밖이다.

## 재도전 후 결과 팝업 잔류 수정

더미 Retry가 Bootstrap을 직접 호출하면 실제 UI Bridge의 RetryResult에 있던 닫기 처리를 거치지 않아 결과 팝업이 남았다. 결과 데이터가 해제될 때 Bridge가 승리·패배 팝업을 함께 정리하도록 변경했다. 버튼별 별도 닫기 처리는 제거했다.

`UIPopupController.CloseResolvedPopup`은 소유 시스템이 완료한 특정 팝업만 제거한다. 상위 메뉴/설정은 유지하고, 팝업 목록·입력 차단·이전 선택 대상 기록을 함께 정리한다. 이미 닫힌 팝업은 이벤트 없이 종료한다. 기존 사용자 닫기 정책은 `CloseTopPopup`에 유지한다.

검증:
- Play Mode `ResultPopupVerification`: 결과 위 메뉴/설정 두 개가 열린 상황, 선택 복원, 입력 차단 유지/해제, 중복 닫기, 닫기 거부 정책과 일반 메뉴 닫기 통과. Selectable의 실제 선택 동작 검증이므로 Play Mode 전용이다.
- 헬에서 실제 패배 후 Bootstrap 직접 Retry: 결과창 비활성, 팝업 수 0, 배치 입력과 전투 시작 복구 확인.
- 잘못된 RunId의 재도전 요청 거절 시 기존 결과창 유지 확인.
- 실제 패배 후 메뉴를 연 상태에서 Bridge Retry: 결과만 닫히고 메뉴/입력 차단 유지, 메뉴 닫기 후 입력 복구 확인.
- 승리는 완주 대신 정산 완료 테스트 결과를 주입하여 승리 팝업 표시와 재도전 시 정리를 확인.
- 런타임 Bootstrap의 설정 참조를 잠시 비워 초기화 실패 유도: 오류 메시지 유지, 잔여 팝업 0, 입력 차단 해제 확인. 원본 SO와 씬은 변경하지 않았으며 참조 복구 후 Play Mode 종료.
- 기존 RunResultVerification 통과. 테스트용 XP/레벨/LP와 폰트 자동 생성 변경 복구.

재도전 요청 거절과 접수 후 초기화 실패는 구분한다. 전자는 결과창을 유지하고, 후자는 소비된 결과창을 닫고 기존 오류 표시를 사용한다. 이전 결과를 다시 복원하는 런 정책은 추가하지 않았다.

## 결과 UI 폰트 연결 후속 수정

사용자 승인으로 InGame 씬의 승리·패배 결과창 TMP 26개에 기존 `DOSGothic Pixel`과 해당 머티리얼을 연결했다. 누락된 폰트 참조를 씬 인스턴스에서만 복구했으며 공용 프리팹에는 Apply하지 않았다. 폰트 파일 원본·크기·레이아웃은 유지한다.

Play Mode에서 두 결과창의 미리보기 데이터를 렌더링해 한글 표시, 대체 네모 문자 0개, 영역 넘침 없음 확인. 패배창 스크린샷 확인 및 Console 오류/경고 0개. 검사 중 자동 갱신된 외부 폰트 파일은 기존 ZIP 내용과 해시를 대조해 복구했다. 앞서 기재한 InGame 결과창의 폰트 경고는 이 수정으로 해소했다. 다른 씬의 폰트 연결은 변경하지 않았다.

## 최종 검증 후 보완

- `ResultPopupVerification`은 기존 EventSystem이 있으면 재사용하고 없을 때만 임시 생성한다. 기존 객체가 없거나 비활성이면 복원을 생략한다. 없는 EventSystem 복원 오류와 중복 활성 경고를 해소했다. 기존 객체 유무 두 경우 모두 Play Mode 재검증 통과, 오류/경고 0개.
- `StageDataSO`에 표시 전용 Display Name을 추가하고 보통/어려움/헬 데이터에 설정했다. 결과 UI Bridge는 StageCatalog의 ID 조회를 통해 표시명을 전달한다. 내부 ID, 라운드와 저장 데이터는 유지한다. 미설정 콘텐츠는 기존처럼 ID를 표시한다.
- 세 표시명과 미등록 ID 대체 동작 자동 검증 통과. 실제 헬 패배 결과에서 `헬 난이도` 표시, 이후 재도전과 팝업/입력 정리 확인.
