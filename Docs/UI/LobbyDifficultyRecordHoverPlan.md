# 로비 난이도 기록 프레임 — 위쪽 호버 확장 구상 v2

## 상태와 범위

- 2026-09-22 디자인 예시 및 시스템 구상. 아직 구현/적용하지 않았다.
- 이번 턴 변경은 이 문서, 프롬프트 기록, 비교 이미지뿐이다. Scene/Prefab/Runtime 코드/실제 기록/저장 데이터는 변경하지 않는다.
- v1의 상시 큰 기록판 대신, 기존 기본 화면의 중앙 난이도 정보판만 호버 시 위로 펼친다.
- 대상 예정: UI_Lobby_MutedPreview > Canvas_Lobby > StageSelection > CurrentStage의 StageRecord.
- 좌우 카드·화살표·마름모 그림·전투 준비 버튼·하단 메뉴는 위치/크기 유지.
- 이미지: [기본/호버 비교](References/LobbyDifficulty/difficulty_record_frame_hover_v2.png).
- 예시 숫자 25 웨이브 / 08:42는 실제 플레이 기록이 아니다.

## 디자인

- 기본 상태: 현재처럼 난이도 이름과 한 줄 설명만 표시한다. 이전 목업처럼 상시 큰 기록판으로 바꾸지 않는다.
- 확장 상태: 판의 폭과 하단 기준선을 고정하고 위쪽 경계만 올라간다.
- 난이도 이름·설명도 하단 고정 영역에 남는다. 기록은 새로 열린 위쪽 공간에 2열로 표시한다.
- 최고 클리어 웨이브/클리어 시간 라벨과 아이콘은 이전 v1보다 작게, 숫자는 라벨보다 한 단계 크게 표시한다.
- 레이블 약 16~18px, 아이콘 18~20px, 값 22~24px를 1920x1080 기준 시작값으로 삼되 실제 Canvas 배율에서 가독성을 검증한다.
- 어두운 암적색 금속, 얇은 고금색 안쪽 선, 검정에 가까운 내부 배경. 확장용 상단은 단정한 모서리로 처리한다.
- 중앙 초상화의 얼굴은 가리지 않는다. 확장은 그림 하단 일부 위에 겹쳐 표시하며 다른 레이아웃을 밀지 않는다.
- 비교 이미지의 상단 '기본 상태/마우스 오버' 제목과 커서는 설명용이며 게임 에셋에 포함하지 않는다.

## 플레이어 동작

| 상황 | 동작 제안 |
| --- | --- |
| 기본 | 축소 상태, 기록 숨김 |
| 중앙 정보판에 진입 | 약 0.08초 후 0.22초 동안 위쪽 확장 |
| 확장 도중 | 기록 영역을 Mask로 드러내며 약간 늦게 페이드인 |
| 펼쳐진 판 안에서 이동 | 열린 상태 유지 |
| 판 전체를 벗어남 | 약 0.10초 이탈 유예 후 0.16초 동안 축소 |
| 빠른 재진입 | 현재 높이에서 자연스럽게 방향 반전, 처음부터 다시 시작하지 않음 |
| 난이도 좌우 전환 | 확장 잠금/축소, 기존 페이드아웃 중 투명 시점에 기록도 교체 |
| 난이도 전환 완료 | 새 표시 확정 후 실제 포인터 위치 재검사, 아직 판 위라면 다시 확장 |
| 로비 숨김/파괴 | 자기 Tween과 구독만 정리, 축소 상태 복구 |

시간은 제안값이며 Inspector에서 수정 가능하게 한다. UI 애니메이션은 기존과 동일하게 unscaled time을 사용한다.

## 리소스 분리

1. 상단 캡: 높이가 변해도 장식 크기는 고정, 위쪽 위치만 이동.
2. 하단 캡 및 기본 명패 장식: 고정.
3. 좌우 레일: 길이만 변경, 가능하면 타일 방식으로 도트 간격 유지.
4. 내부 어두운 배경: 단순 9-slice 또는 별도 Image.
5. 가로/세로 구분선, 트로피, 모래시계: 각각 독립 Sprite.
6. 난이도명·설명·기록 라벨·숫자: TMP, 이미지에 글씨를 굽지 않는다.

전체 프레임의 localScale.y를 늘리지 않는다. 바닥 pivot(0.5, 0) 기준으로 표시 높이만 변경하고, 기록 Reveal 영역은 RectMask2D로 제어한다. 확장 전체 이미지 한 장을 단순 확대하는 방식도 사용하지 않는다.

## 책임 분리와 기존 코드 연동

새 표시 컴포넌트 후보: UILobbyDifficultyRecordPanel.

- 맡는 일: 포인터 상태, 펼침/접힘, 작은 기록 표시, 자기 Tween 정리.
- 맡지 않는 일: 난이도 선택, 전투 시작, 플레이 기록 계산, 저장.
- 정적 설정: 높이/시간/색/아트 및 기존 Catalog의 이름·설명.
- 런타임 상태: 현재 펼침 정도와 표시 중 난이도/기록 스냅샷.
- 저장 데이터: 향후 별도 기록 제공자가 관리한다. 현재 Catalog SO에 최고 기록을 저장하지 않는다.

기존 UILobbyDifficultySlotView.Bind(entry, artwork)는 전환의 투명 시점에도 호출된다. 중앙 슬롯에만 선택적 기록판 참조를 추가하고 이 바인딩 시점에 기록도 표시하도록 제안한다. SelectionChanged만으로 기록을 바꾸면 페이드인 중에는 이전 기록이 남을 수 있으므로 피한다.

기존 UILobbyDifficultySelector에 TransitionStateChanged(bool) 같은 선택적 표시 알림을 추가하는 방안을 제안한다. 시작 시 호버를 잠그고, 완료/취소/즉시 변경 시 올바른 항목 바인딩 후에 잠금을 푼다. CancelTransition 내부에서 표시 복구보다 먼저 재확장을 허용하지 않는다. 이는 후속 구현에서 추가할 API이며 아직 존재하지 않는다.

기록판 Visual은 기존 caption CanvasGroup 아래에 두어 난이도 전환의 투명도를 상속받는다. 호버 컴포넌트는 부모 alpha를 제어하지 않고 자기 높이와 기록 내용용 자식 CanvasGroup만 제어한다.

## 포인터 판정과 중단 안전성

- 현재 캡션 CanvasGroup은 blocksRaycasts=false이다. 그 아래에 포인터 콜백만 추가해서는 호버가 잡히지 않을 수 있다.
- 별도 투명 HitArea를 캡션의 표시 전용 그룹 밖에 두고 프레임의 실제 영역에 맞춘다.
- 기본 상태의 감지 범위는 축소 프레임, 확장 상태의 감지 범위는 펼쳐진 전체 프레임이다.
- HitArea가 전투 준비/화살표/옆 난이도까지 덮지 않도록 확인한다.
- 자식 글자/아이콘은 Raycast Target을 끄고 포인터 영역을 분절하지 않는다.
- 축소 중에는 감지 영역 변화로 enter/exit가 반복되지 않도록 이탈 유예 후 실제 위치를 재검사한다.
- 재진입 시 자신의 Tween만 Kill(false)하고 현재 높이/alpha에서 이어간다. 전역 Kill 금지.
- 비활성화/파괴 시 이벤트 해제, 자기 Tween 종료, 축소 상태로 복구한다.

## 기록 표시 규칙 — 데이터 연결 시 확정

- 난이도별 기록을 분리해 읽는다. 없으면 '기록 없음' / '--:--'처럼 표시하며 가짜 숫자를 넣지 않는다.
- '클리어 시간'이 최고 웨이브를 달성한 해당 플레이의 시간인지, 전체 난이도 완주 최단 시간인지 아직 확정되지 않았다.
- 후속 실제 데이터 연결 전에 집계 기준을 확인한다. 웨이브 최고값과 다른 플레이의 시간을 임의로 한 쌍처럼 표시하지 않는다.
- 이번 디자인에서는 예시 값만 사용한다.

## 적용 전 확인과 테스트

- Scene/Prefab 변경은 사용자 확인 후 Unity Editor/MCP로만 진행한다.
- 예상 충돌 파일: UI_Lobby_MutedPreview.unity, 중앙 슬롯/전환 제어 코드. 다른 화면/실제 전투/저장 코드는 범위 제외.
- Inspector: Panel/TopCap/BottomCap/레일/Reveal Mask/기록 TMP/아이콘/HitArea/Selector 참조.
- Play Mode: 기본화면 동일, 하단/버튼 기준선 고정, 확장 중 얼굴 가림 없음, 양끝 난이도 경계 그대로.
- 빠른 진입/이탈, 글자 위 이동, 호버 도중 난이도 변경, 전환 도중 숨김/재활성화, Time.timeScale=0.
- 기록 없음/서로 다른 기록/즉시 선택 변경/아트 세트 교체.
- 해상도와 CanvasScaler별 작은 글자 가독성, 버튼 Raycast, MissingReference/NullReference, Console 확인.
- 이번 턴에는 새로운 동작을 구현하지 않았으므로 위 동작 테스트와 컴파일 검증은 후속 구현 단계에서 수행한다.
