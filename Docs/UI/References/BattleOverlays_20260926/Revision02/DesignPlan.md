# 전투 결과 공통화 / 레벨업 증강 등급 표현 설계안

2026-09-26 · 이미지 레퍼런스와 구현 설계만 작성. 이하 Prefab·클래스·SO 이름은 **제안명**이며 아직 생성하거나 연결하지 않았다.

## 결정 기준

- 레벨업: 기존 02 Noble Velvet의 벨벳 3열 카드 유지.
- 승리/패배: 기존 **패배 03 Runic Altar**를 공통 레이아웃 기준으로 사용.
- 공통 자산을 두 화면에서 그대로 공유하고 상태에 필요한 이미지와 문구만 교체한다.
- 동적 글자·수치는 PNG에 넣지 않고 Unity Text/TMP로 분리한다.
- 이번 이미지의 통계, 경험치, 공격력 +10% 등은 시각 비교용 예시다.

### 기존 차이와 통일 방향

기존 승리 03은 계단·기둥이 있는 제단, 세로 정렬 통계 아이콘, 별도 경험치 줄이었다. 패배 03은 상단 문장과 가로로 넓은 기록판, 아이콘 좌측/텍스트 우측의 세 열, 경험치 한 줄이었다. 이번에는 후자를 공통 구조로 채택했다.

상단부터 **문장·룬 → 난이도 → 결과 제목 → 통계 3열 → 경험치 1줄 → 로비로 버튼**이다. 승패 사이에서 폭·중심축·행 높이·폰트 위계·버튼 위치를 바꾸지 않는다. 생성 이미지에는 미세한 픽셀 차이가 남을 수 있으므로 실제 구현은 두 통 이미지를 번갈아 쓰지 않고 동일 Prefab의 자산을 공유한다.

### 최소 리소스 분리

| 구역 | 공통 리소스 | 승리 변경 | 패배 변경 |
| --- | --- | --- | --- |
| 후면 | 기존 전투 화면 + 검정 Image 오버레이 | 동일 | 동일 |
| 상단 문장 | 마름모 금속 프레임 1종, 문장 표시 영역 | 온전한 왕관/승전 문장 | 균열 왕관/쇠락 문장 |
| 룬 | 중립색 룬 링 1종 | 고금색 tint, 낮은 강도의 빛 | 어두운 적색 tint, 약해진 빛 |
| 깃발 | 깃대·체인·부착 위치 | 온전한 천 스프라이트 | 해진 천 스프라이트 |
| 제목 장식 | 동일 위치의 장식 마스크 | 고금색 tint | 적색 tint |
| 기록판 | 짙은 바탕, 실버 외곽 프레임, 구분선 | 동일 | 동일 |
| 통계 | 동일한 마름모 아이콘판, 모래시계·해골·배치 아이콘 | 클리어 시간 | 플레이 시간 |
| 경험치 | Track / Fill / 눈금 | 전달받은 기록으로 갱신 | 전달받은 기록으로 갱신 |
| 로비로 | 공통 버튼 Normal / Hover / Pressed, 동일 TMP | 동일 | 동일 |

왕관·깃발의 상태는 전용 스프라이트로 교체하고, 룬과 은은한 빛은 공통 회색/흰색 자산의 색상으로 처리한다. 기록판을 승리용 금색/패배용 실버로 따로 만들지 않는다.

### 배치·스프라이트 규약

- 동일 기준 해상도(1920×1080 제안), CanvasScaler 설정과 앵커를 공유한다.
- 좌우 통계 3칸은 같은 폭, 값의 시작 위치와 라벨 기준선을 공유한다.
- 문장 이미지 2개는 같은 PNG 캔버스 크기, 같은 alpha 안전영역, 같은 중심 pivot (0.5, 0.5), 같은 PPU로 준비한다. 각각 다르게 tight crop하지 않는다.
- 깃발 이미지는 위쪽 매다는 지점을 공통 기준점으로 맞추며 해짐으로 외곽이 줄어도 부착 위치는 바뀌지 않는다.
- 금속 외곽의 장식 코너는 비율을 고정한다. 폭 가변이 필요한 직선 몸체만 9-slice로 사용하고 문장/코너 장식을 잡아늘리지 않는다.
- 경험치 바는 표시용 Slider 또는 Filled Image로 분리한다. Slider 사용 시 interactable=false이며 0~1 정규화 값만 전달받는다.
- LV UP 표시는 승리 여부가 아니라 실제 레벨 증가 여부로 제어한다. 레벨업하지 않았을 때는 숨긴다.
- 난이도, 승패 제목, 시간 라벨, 통계 값, 경험치, 레벨, 버튼 문구는 전부 Text/TMP다.
- 생성 레퍼런스의 LV.20 같은 표기는 구현 시 공통 텍스트 포맷으로 정규화한다.

### 기존 구조를 보존하는 연결안

현재 Popup_StageClear / Popup_Defeat에는 서로 대응하는 Frame, Difficulty, ResultTitle, Records, Reward, LevelProgress, LobbyButton, Illustration_Placeholder가 있다.

| 제안 요소 | 책임 | 별도로 분리하는 이유 |
| --- | --- | --- |
| BattleResultContent.prefab | 상단 문장부터 기록·버튼까지 한 가지 공통 배치 | 두 팝업의 배치가 다시 어긋나는 것을 방지 |
| UIBattleResultView | 전달된 화면 데이터와 시각 프리셋을 표시 | 전투 기록 계산·저장과 UI를 분리 |
| BattleResultVisualCatalogSO | 승리/패배 문장, 깃발, 룬/강조색의 고정 설정 | 아트 교체와 톤 조정을 Inspector에서 관리 |
| BattleResultDisplayData | 시간·처치·배치·획득 XP·레벨·XP 비율·레벨업 여부의 일시적 표시 데이터 | 현재 전투 기록을 SO에 저장하지 않음 |

기존 두 Popup 루트와 각 로비 이동 연결은 유지하고, 내부에 공통 Content Prefab을 중첩하는 방향을 우선한다. 이번 설계는 기존 닫기·씬 이동·보상 지급 정책을 변경하지 않는다.

전투 종료 처리에서 확정한 기록을 UI에 전달하고, UI는 승패 프리셋만 선택해 표시한다. 결과창을 다시 열어도 XP를 중복 지급하지 않도록 **UI는 보상을 지급하지 않는다**. SO에는 실제 기록, 현재 XP 또는 현재 승패 상태를 기록하지 않는다.

## 2. 레벨업 등급 표현 4안

모든 안은 왼쪽 실버 / 가운데 골드 / 오른쪽 플래티넘을 같은 증강으로 비교한다. 실제 플레이에서 세 등급을 동시에 뽑는 제안이 아니다.

| 안 | 이미지 | 핵심 표현 | 판단 |
| --- | --- | --- | --- |
| 01 금속 프레임형 | [이미지](Rarity_01_MetalFrame.png) | 마름모와 카드 외곽의 금속 재질 | 직관적이나 실버/플래티넘은 색만으로 비슷함 |
| 02 등급 리본형 | [이미지](Rarity_02_RankRibbon.png) | 공통 카드 + 작은 독립 등급 리본 | 작은 크기에서 읽기 쉽고 자산 교체가 단순 |
| 03 문장 장식형 | [이미지](Rarity_03_HeraldicCrest.png) | 실버 단정한 프레임 / 골드 잎 장식 / 플래티넘 왕관·날개형 금속 | 형태로도 구별되어 우선 추천 |
| 04 벨벳 문양형 | [이미지](Rarity_04_VelvetWeave.png) | 자수·내측 문양과 절제된 재질 변화 | 분위기를 살리는 보조 표현; 등급 차이는 가장 약함 |

실제 제작은 03을 기준으로 장식이 들어가는 영역을 동일 크기로 예약하고, 모든 등급의 흰색 본체 아이콘과 본문 영역은 같은 크기로 유지하는 방향을 추천한다. 화려한 등급에서도 장식 때문에 이름·설명 공간이나 클릭 영역이 줄어들지 않아야 한다. 등급명은 모든 안에서 명시한다.

### 기존 코드에서 확인한 사실

- Assets/01.Scripts/Augment/AugmentData.cs: tier 정수 1~3, TierName(1)=실버 / 2=골드 / 3=플래티넘.
- Assets/01.Scripts/Augment/AugmentRun.cs: Draw3는 해당 단계의 **같은 등급** 후보에서 중복 없이 최대 세 개를 뽑는다.
- 현재 기본 데이터는 런 한정 유니크 증강(maxStack=1)이며, 로비의 영구 특성 성장과 별개다.
- 그래서 새 등급 레퍼런스에서 기존 미연결 자리표시자인 현재 레벨 0을 제거했다. 실제 코드나 로비 특성을 변경한 것은 아니다.
- 현재 AugmentData에는 스프라이트/등급색 설정이 없으며, 이번 작업에서 필드를 추가하지 않았다.

### 등급 리소스 / 데이터 분리안

| 요소 | 공통으로 유지 | 등급별 교체 |
| --- | --- | --- |
| 카드 몸체 | 벨벳 바탕, 본문 바탕, 크기·클릭 영역 | 필요 시 옅은 자수만 |
| 특성 아이콘 | 흰색 본체, 같은 표시 영역 | 아이콘 자체는 증강 종류로 교체, 등급과 별개 |
| 마름모 테두리·장식 | 고정 캔버스/중심/PPU | 실버·골드·플래티넘 프레임/문장 3종 |
| 등급 표식 | 동일 위치와 글자 크기 | 실버·골드·플래티넘 라벨과 금속색 |
| 호버·선택 | 별도 Highlight Image와 공통 클릭 피드백 | 등급 프레임을 덮어 바꾸지 않음 |
| 설명·효과 | TMP와 고정 여백 | AugmentData에서 전달받은 내용 |

제안: AugmentVisualCatalogSO에서 augmentId와 아이콘의 매핑, tier와 GradeVisual(프레임·장식·리본·색상)의 매핑을 분리 관리한다. AugmentCardView는 AugmentData의 tier를 읽어 표시만 한다. UI용 카탈로그가 게임플레이 tier/추첨 가중치/효과량/선택 이력을 별도로 복제하여 관리하지 않게 한다.

동적 상태(선택한 증강, 현재 런 기록)는 기존 AugmentRun이 소유한다. 시각 자료는 SO, 이름·설명·효과는 기존 증강 데이터, 선택 동작은 기존 로직을 통해 전달한다. 실제 화면 연결이 아직 없으므로 차후 구현 전에 어떤 런타임 진입점을 사용할지 확정해야 한다.

## 3. 이후 구현 범위와 확인 순서

이번에는 아래 작업을 수행하지 않았다. 채택안 확정 및 Scene/Prefab 변경 승인 후 진행한다.

1. 공통/상태별 스프라이트 원본 생성과 투명 배경·동일 여백 준비.
2. 공통 결과 Content와 레벨업 카드 1종 제작, Text/TMP 연결.
3. 결과 프리셋 2종, 증강 등급 표시 프리셋 3종 연결.
4. 미리보기 데이터로 승패와 모든 등급을 각 1회 확인.
5. 기존 팝업의 열기·로비로·선택 연결을 확인하고 실제 런타임과 연결하는 범위를 별도로 확정.

Inspector 확인: 동일 크기·pivot·PPU, 아트의 raycastTarget=false, 프레임/문구 참조, 글자 scale=(1,1,1), 같은 버튼 영역, Slider 값과 Fill 연결, null/누락 프리셋 처리.

Play Mode 확인: 승패 레이아웃 동일, 시간 라벨만 올바르게 전환, XP/레벨업 조건 표시, 로비로 1회 동작, 동일 등급 3택1 유지, 호버와 등급 구분, 선택 중복 방지, Console 오류/누락 참조. 실제 보상 저장·전투 계산은 UI에 추가하지 않는다.

이번 변경 파일은 Revision02의 PNG 및 설계/프롬프트 MD뿐이다. Scene/Prefab/Meta/Runtime/Editor/ProjectSettings/Packages/Figma 원본은 변경하지 않았다.
