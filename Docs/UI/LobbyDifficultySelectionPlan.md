# 로비 난이도 선택: 아트 / 시스템 구상

## 상태와 범위

- 사용자 요청: StageSelection을 쉬움 / 보통 / 어려움 난이도 선택으로 확장한다. 최초 이동형 구상은 아래 승인된 고정 프레임 갱신형으로 변경했다.
- 승인된 적용: 01·02 이미지 세트 준비, 02 용사군 기본 적용. 테두리/캡션 위치 고정, 페이드아웃 → 내용 교체 → 페이드인, 내부 그림만 짧게 좌우 이동한다.
- Scene Change Plan 범위 승인을 받아 구현했다. 실제 편집 위치·코드·검증은 `Docs/UI/LobbyDifficultySelection.md` 참고.
- 대상: `Assets/00.Scenes/UI_Flow/UI_Lobby_MutedPreview.unity > Canvas_Lobby > StageSelection`.
- `Canvas_LobbyOverlays`, 레벨 HUD, 도감·업적·스킬·특성, 다른 Scene, 실제 전투 밸런스와 저장 규칙은 이번 1차 적용 범위에서 제외한다.
- 작업 시작 시 기존 변경은 `Canvas_UnitCodex.prefab`뿐이며 이 파일은 보존한다.

## 확인한 기존 구조

- `PreviousStage`, `CurrentStage`, `NextStage_Locked`에는 `UILobbyStageCardView`와 독립 Artwork / Mask / Frame / Lock 레이어가 있다. 기존 표시 컴포넌트를 재사용한다.
- 현재/양옆 카드 크기는 540×540 / 430×430이다. 실제 그림의 마름모 대각선은 카드 크기의 약 80%이므로 중앙 약 432 / 양옆 약 344 픽셀 영역이다.
- 정사각형 Mask를 45도로 회전하고, 내부 ArtworkRoot는 역회전한다. 그림을 회전시키거나 프레임까지 한 장으로 합칠 필요가 없다.
- PreviousArrow / NextArrow는 현재 비활성이고 OnClick 연결이 없다.
- `CurrentStage` 아래에 StageRecord / StartButton이 들어 있다. 변경된 고정 프레임 방식에서는 부모를 움직이지 않으므로 두 영역의 부모/위치는 그대로 유지한다.
- 전투 준비는 `UISceneNavigator.LoadScene("Assets/00.Scenes/UI_Flow/UI_Battle.unity")`만 연결되어 있다. 선택 난이도는 전달하지 않는다.
- DOTween 1.3.030 및 UI 모듈이 설치되어 있어 추가 패키지가 필요 없다.
- StageDataSO에는 보통 `StageNormal30`, 어려움 `StageHard50` 및 더미 데이터가 있다. 쉬움 전용 데이터는 현재 검색/AssetDatabase 목록에서 확인되지 않았다. 기존 개인 Sandbox의 난이도 선택을 로비에 그대로 끌어오지 않는다.

## 아트 방향: 4안 × 3난이도

모든 비교판의 열 순서는 쉬움 / 보통 / 어려움이다. 같은 중립 프레임을 사용해 그림 자체의 위협도가 비교되도록 한다. 선택 상태의 붉은 프레임과 난이도 표현은 분리한다.

| 안 | 쉬움 | 보통 | 어려움 |
| --- | --- | --- | --- |
| 01 마왕성 공성전 | 성을 향하는 소수 정찰대 | 성문에 접근하는 기사대 | 정예 공성군과 공성 장비 |
| 02 용사군의 위협 | 가벼운 장비의 보병 | 중무장 숙련 기사 | 정예 성기사 지휘관과 군단 |
| 03 양 진영의 격돌 | 소규모 방어전 | 기사대와 본격적인 교전 | 성기사 군단의 강한 압박 |
| 04 성문을 향한 진군 | 성문 밖의 소수 정찰병 | 다가오는 방패·창병 진형 | 성문을 가득 메우는 정예 침공군 |

- 플레이어는 마왕성 방어자이므로, 어려움을 ‘플레이어 성이 강해짐’이 아니라 적의 장비·병력·압박이 커지는 모습으로 표현한다.
- 기존 고풍스러운 다크 판타지 도트 톤을 유지한다. 원색·과한 발광 대신 먹색, 낡은 상아색, 탁한 적색, 제한적인 고금색을 쓴다.
- 인물 머리, 무기 충돌점, 주요 탑을 마름모 중앙 약 55% 안에 배치한다. 꼭짓점에는 하늘·안개·길 등 잘려도 자연스러운 요소를 둔다.
- 최종 게임용 그림은 정방향 정사각 PNG 3개로 생성한다. 프레임·사슬·문자·난이도 표시는 이미지에 굽지 않고 기존 레이어와 TMP로 관리한다.
- 전체 생성 프롬프트: `Tools/Art/lobby_difficulty_reference_prompts.md`.

## 권장 선택 흐름

- 초기 선택은 보통. 쉬움 / 보통 / 어려움 순서를 유지한다.
- 중앙 카드가 선택값이고 붉은 프레임·기본 크기, 양옆은 중립 프레임·약 80% 크기로 표시한다.
- 오른쪽 버튼: 다음 난이도로 갱신. 왼쪽 버튼: 이전 난이도로 갱신. 카드 테두리와 글자 위치는 이동하지 않는다.
- 쉬움에서 왼쪽, 어려움에서 오른쪽 버튼은 비활성. 처음과 끝이 이어지는 무한 순환은 하지 않는다.
- 난이도 3개는 1차 선택 UI에서 모두 선택 가능하게 제안한다. 현재 NextStage_Locked의 고정 잠금은 실제 해금 정책과 별개이므로 난이도 정책으로 임의 전환하지 않는다. 추후 해금 연동 시 런타임 해금 상태를 입력받는다.
- 난이도 이름은 각 카드 아래 TMP, 선택 난이도 설명과 기록 영역은 고정 영역에 표시한다. 실제 난이도별 기록이 없으면 공용 ‘최고 도달 40’을 난이도별 기록인 것처럼 사용하지 않는다.

- 선택 인덱스/진행도/해금 상태를 Catalog SO에 저장하지 않는다.
- 카탈로그와 선택 제어부를 분리하는 이유는 아트·문구 편집이 애니메이션/입력 로직에 영향을 주지 않도록 하기 위해서다.
- 첫 구현은 UI 난이도 선택과 선택값 제공까지다. 실제 전투 시작 어댑터는 쉬움 데이터·런 시작 계약을 확인한 다음 연결한다. ‘쉬움’ 선택인데 보통 전투 데이터를 몰래 재사용하지 않는다.
- 기존 전투 준비의 Scene 이동은 유지하되, 1차 선택이 실제 전투 난이도 변경까지 보장하지 않는다는 점을 명시한다. 이 연결까지 즉시 필요하면 쉬움 StageDataSO 기준과 전투 Scene 연결 범위를 먼저 확정한다.

## DOTween 전환 설계

- 중앙 붉은 프레임 / 양옆 중립 프레임, 캡션, 마름모 Mask, 카드 부모 위치·크기를 유지한다. 프레임/글자는 이동하지 않는다.
- DOTween Sequence에서 0.14초 페이드아웃(OutQuad), 표시 교체, 0.21초 페이드인(OutCubic)을 실행한다. 전용 ArtworkMotion만 카드 폭의 6%를 좌우 이동한다.
- Inspector에서 Fade Out Duration / Fade In Duration / Artwork Slide Ratio / Ease를 조절할 수 있다. Slide Ratio=0이면 위치 이동 없이 갱신한다.
- `SetUpdate(true)`로 Time.timeScale=0에서도 UI 전환이 동작하게 한다.
- 전환 중 중복 입력과 전투 준비 입력을 잠시 차단하고, 완료 시 선택값/표시를 확정하고 이벤트를 한 번 발생시킨다.
- 빠른 연타로 Sequence가 쌓이지 않게 하나만 소유한다. 비활성/파괴 시 자신이 만든 Sequence만 종료하고 확정된 선택 위치로 정리한다. DOTween 전체 Kill은 호출하지 않는다.
- 완전히 투명한 순간에 Artwork와 TMP 내용을 교체한다. 자리별 Frame Sprite는 교체하거나 이동하지 않으며 투명도만 바꾼다. 원본 PNG를 보존한다.

- 코드만으로 가능한 부분: 데이터 형식, 선택 상태, 전환/입력 처리, 검증 코드.

- 충돌 위험: `UI_Lobby_MutedPreview.unity`. 에셋과 새 SO의 .meta는 Unity가 생성한다. Scene/Prefab/.meta 텍스트 직접 편집은 하지 않는다.
