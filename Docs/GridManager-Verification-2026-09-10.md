# 블록·유닛 분리 검증 (2026-09-10)

Unity 6000.3.22f1, feat/grid-manager/5, JOB_KIMGUN에서 검사했습니다.

## 변경

- BlockPlacement와 UnitPlacement 분리. 유닛은 요구 모양 ID와 배치된 블록 인스턴스 ID를 관리합니다.
- BlockShapeSO로 기존 모양 스크립트 이름 변경. Unity AssetDatabase 사용, 기존 스크립트 GUID 및 6종 SO 참조 보존.
- GridUnitDataSO 및 더미 매핑 6종 추가. Basic→single, Mage→corner_three, 나머지는 모양별 더미입니다.
- 블록 선택 영역과 유닛 카드 UI 분리. 블록은 R 회전, 유닛은 블록 기준 칸 표시를 드래그합니다. Shift+드래그는 점유 중인 블록을 선택합니다.
- 블록 이동/회수 확정 시 위의 유닛을 카드로 반환하며, 취소/무효 드롭에서는 블록과 유닛 연결 모두 보존합니다.
- 코드, 데이터, 입력/표시, 검사, 팀 공유 문서를 갱신했습니다. 바닥 크기/확장 데이터, 마왕 칸 규칙은 유지했습니다.

## 통과한 검사

최종 컴파일 오류 및 Console 오류·경고 0, 씬/프리팹 Missing Script 0, 카탈로그의 블록 6종·유닛 6종 참조 유효, 신규 에셋 meta 누락 없음. Play를 종료하고 에셋을 저장했습니다.

- 6종 모양의 4방향 배치·원래 모양 복귀.
- 블록 경계·바닥 없음·블록 겹침 차단, 자기 기존 점유 허용.
- 빈 블록만 놓았을 때 전투 시작 차단.
- 잘못된 요구 모양 및 블록 없는 바닥에 유닛 배치 차단.
- 회전된 같은 모양 블록 및 기준 칸 외의 점유 칸에 유닛 배치 허용.
- 블록 전체에 유닛 1기 제한, 자기 기존 블록으로 재배치 허용.
- 같은 모양의 다른 블록으로 유닛만 이동, 이전 블록의 연결 해제.
- 블록 드래그 중 반환 예정 카드만 표시하고 실제 상태/확정 이벤트 유지.
- 블록 이동 확정 시 유닛 반환과 블록 변경 후 확정 이벤트 1회 발생.
- 블록 회수 시 유닛 반환, 유닛만 회수 시 블록 유지, 모두 바닥 보존.
- 무효 드롭 및 취소 시 블록 위치·회전·유닛 연결 복구.
- 실제 유닛 1기 조건, 최초 준비 스킵 금지, 확장 미완료 시 시작/스킵 차단.
- 기존 1×2 확장 14회, 8×5 상한, 연결 판정, 배치 불가능한 확장 후보 검사.
- Play 모드의 UI Toolkit 포인터·R/Esc·Shift 이벤트로 위의 카드/블록 흐름 검사.
- 유닛 요구 모양 불일치의 빨강 고스트, 적합한 모양의 초록 고스트 표시 색상 검사.
- 1920×1080 Game View에서 분리된 블록/유닛 카드와 마법사 고스트를 확인했습니다. 블록 카드 아이콘이 영역을 벗어나지 않도록 크기를 조정했습니다.

## 범위 및 한계

유닛은 점·이름으로 표시하는 더미입니다. 실제 캐릭터 프리팹, 팀원 SO, StageManager 및 파일 저장 통합은 아직 미연결입니다. 준비 씬 재로드 시 상태 보존은 아래 추가 검사에서 확인했습니다. OS 마우스 장치 자체를 조작한 검사는 아니며, UI Toolkit 이벤트가 실제 등록된 콜백으로 전달되는 경로를 검사했습니다. 다른 해상도 및 배포 빌드 검사는 수행하지 않았습니다.

백그라운드 Game View 검증 동안만 Application.runInBackground를 활성화한 후 원래 false로 복원했습니다. 검증 캡처는 Library/GridVerification에 저장합니다. Notion 수정·커밋·Push·병합은 수행하지 않았습니다.

## 추가 검증 — 세션·보상·배치 전달

보상 규칙은 유닛 A / 유닛 B / 1×2 확장 중 하나 선택이며, 유닛 선택 시 해당 유닛 1기와 요구 블록 1개를 지급합니다.

- GridVerification: PASS. 보상 ID 중복·오래된 요청·요구 모양 불일치 거부, 일괄 지급 이후 이벤트, 준비 스킵 제한, 불변 전투 스냅샷, XY/XZ 중 XZ 좌표 변환과 별도 마왕 위치, 새 실행 초기 상태를 확인했습니다.
- 제자리 블록 드롭에서 유닛 유지와 화면 갱신만 발생하고, 실제 이동·회전에서 유닛이 회수되는 회귀 검사도 통과했습니다.
- GridSessionPlayVerification: PASS. 새 Play 세션에서 8회 보상 선택을 반복해 매회 유닛/블록 1개씩 추가되고 중복 선택이 거부됨을 확인했습니다. 누적 카드 마지막 항목에 ScrollView로 접근했습니다. SceneManager.LoadSceneAsync로 준비 씬을 실제 재로드한 뒤 동일 Session과 유닛 14개, 필수 확장 상태가 유지되었으며, 확장 배치 후 전투 스냅샷이 바닥 14칸/배치 유닛 1기를 전달했습니다.
- GridPlayVerification: 별도 새 Play 세션에서 PASS. 기존 실제 UI Toolkit 포인터/키 콜백 경로를 재검증했습니다.
- Unity 스크립트 리로드 후 위 검증을 실행했으며 Console 오류·경고 0건입니다. 새 스크립트의 .meta는 Unity가 생성했습니다.

단독 프로토타입의 세션 소유자와 더미 보상 공급자를 검증한 결과이며 실제 Stage 서비스, 지급 확률, 전투 프리팹, 합성, 최종 피그마 화면 연결 검증을 대체하지 않습니다. 아래 연결 경계 보강에서는 명시적 Bootstrap 구성을 위해 Grid 프리팹과 JOB_KIMGUN을 Unity API로 갱신했습니다.

## 추가 검증 — Grid 연결 경계 보강

- IGridPreparation은 Session만 구현하며 GridManager에 public 전투 시작/종료 메서드가 없음을 확인했습니다.
- 생성 직후 준비 허용 대기, 첫 라운드 스킵 금지, 외부 canSkip=false 반영을 검증했습니다.
- 일반 보상을 받은 뒤에도 준비 허용 전에는 시작·드래그가 차단됩니다. 확장도 허용 후 배치해야 시작할 수 있습니다.
- 다른 RunId, 이전/미래 라운드, 중복 전투 종료, 오래된 보상 요청, 소비한 보상 ID 재사용을 거절합니다. 요구 모양 불일치는 요청을 소비하지 않습니다.
- 종료 시 진행 중 드래그를 취소하고 배치·진행·콘텐츠 추가를 차단합니다. 이전 RunId로 새 실행을 열 수 없습니다.
- Play 검사에서 누적 보상·스크롤·씬 재로드를 새 진행 API로 확인했습니다. 별도 화면은 주입 누락 메시지를 표시하고 Host를 자동 생성하지 않으며, 더미 카탈로그 없이 외부 Session에 연결됩니다. 활성 연결 덮어쓰기를 거절하고 종료 후 화면 입력 해제·재활성화 시 종료 상태 유지도 확인했습니다.
- 프로토타입 Bootstrap은 Unity API로 프리팹과 JOB_KIMGUN의 해당 Grid 객체에만 구성했습니다. 실제 Stage 소스는 수정하지 않았습니다.
- API 사용 순서는 GridManager-TeamGuide.md의 최신 연결 명세를 따릅니다. 위의 이전 단계 검증 기록에 나온 자동 준비 진입은 이번 보강으로 분리되었습니다.
- 최종 결과: GridVerification, GridSessionPlayVerification, GridPlayVerification 모두 PASS. Console 오류·경고 0건, JOB_KIMGUN Missing Script 0개, Grid Bootstrap 1개를 확인했습니다. 검증 후 Play를 종료하고 runInBackground를 원래 false로 복원했습니다. 새 스크립트 .meta 누락이 없습니다.
