# 준비 배치 QA 후속 구현 — 2026-09-25

## 조작 및 규칙

- 준비 단계에서 유닛 > 발판 > 확장 영역 순서로 선택한다.
- 확장 영역에 호버하면 지급 당시 1×2 묶음 전체를 표시한다. 해당 묶음에 유닛이나 발판이 남아 있으면 이동할 수 없다.
- 확장 묶음은 드래그로 이동하고 R로 회전한다. 초기 4×3 영역은 고정이며 확장 묶음은 보관하거나 삭제할 수 없다.
- 이동 중 기존 바닥은 유지한다. 확정할 때 경계, 중복, 전체 영역의 상하좌우 연결을 검사한다. 실패·Esc·보관함 드롭 시 원위치를 유지한다.
- 기존 확장을 옮겨도 바닥 칸 수와 새 확장 보상의 필수 배치 상태는 바뀌지 않는다.
- 유닛과 발판은 R로 시계 방향 90도 회전, F로 현재 화면 기준 좌우 반전한다. 마우스로 잡은 칸을 유지하며 즉시 고스트를 갱신한다.
- 반전은 점유 모양에만 적용한다. 유닛 외형과 공격 방향은 변경하지 않는다. 상하 반전 단축키는 추가하지 않는다.
- 준비 중 유닛 점유 칸은 옅은 빨강, 합성 후 배치 오류는 진한 빨강과 테두리로 표시한다. 드래그 유닛의 이전 점유 표시는 제외한다. 고스트는 가능 초록/불가 빨강이며 전투에는 준비 표시를 숨긴다.

## 연결 지점

- `ExpansionPlacement`: 지급된 확장 묶음의 ID/형상/위치/회전을 보존한다.
- `GridManager.Expansions`, `BeginExpansionDrag(id)`: 기존 확장 재배치. 인수 없는 호출은 새 확장 보상 배치를 유지한다.
- `GridManager.GetExpansionMoveFailure`, `SetHoveredCell`: 이동 가능 여부 및 호버 표시용 읽기/입력 경로.
- `GetOccupiedCells(excludedUnitId)`, `GetInvalidCells(excludedUnitId)`: 준비 화면 표시 데이터. 제외 인수는 표시 전용이며 실제 전투 시작 검사는 전체 유닛을 대상으로 한다.
- `FootprintDefinition.GetCells` → `BlockPlacement/UnitPlacement.GetCells` → 배치 판정/미리보기/보관함 아이콘/전투 확정본이 같은 반전 계산을 사용한다.
- `IsMirrored`는 배치 객체와 `GridDeployedUnit`에 포함한다. 기존 생성자 호출은 기본 false로 호환된다. 합성은 대상 유닛의 방향을 유지한다.
- 전투에서는 확정본 `Cells`를 사용하면 성급·회전·반전이 모두 반영된다. 콘텐츠 SO 원본은 변경하지 않는다.
- 확장 이동의 `LayoutChanged`는 성공한 확정에만 발생한다. 미리보기와 실패는 배치 변경으로 통지하지 않는다.

## 검증 결과

Unity 6000.3.22f1 Editor에서 다음 검사를 통과했다.

- `GridPlacementQAVerification`: 연결 다리 이동 거부, 초기 영역/경계/중복 보호, 칸 수 유지, 이동 취소, 확장 보관 금지, 새 확장 필수 배치 유지, 모든 회전 상태에서 F 두 번/R 네 번 복원, 성급별 점유·합성·보관·전투 확정본의 반전 유지.
- `GridPlacementQAPlayVerification`: 빈 Play 씬에서 실제 UI Toolkit 포인터/키 이벤트로 호버·드래그·R/F·Esc·보관함 반환·재배치·전투 입력 잠금을 검사했다. 월드 표시 오브젝트도 검사했다.
- 기존 `GridConnectivityVerification`, `GridVerification`, `GridFusionVerification`, `GeneralRewardVerification`, `InGameVerification`, `RunResultVerification` 통과.
- 실제 InGame: 첫 전투 후 확장 보상을 받고 준비로 진입했다. 런타임 테스트용 3성 유닛으로 발판 부족 오류 표시, 정상 점유 표시, 확장 묶음 호버를 화면에서 확인했다. 발판 보충 후 반전된 4칸 유닛 배치와 확장 이동(14칸 유지), 전투 시작 요청 성공 및 이후 보상 단계 도달을 확인했다.
- 테스트 데이터는 런타임에서만 생성했으며 씬·프리팹·콘텐츠 SO에 저장하지 않았다.
- 이번 수정 이후 전체 30/50라운드 완주와 실행 빌드 검증은 수행하지 않았다. 사용자 보고의 쉬움 30라운드 결과 화면 검증은 이번 수정 전 기록이다.

자동 검사는 Editor 전용이며 플레이어 빌드에 포함되지 않는다. 실행 테스트 메뉴는 빈 Play 씬을 요구하고 생성한 테스트 오브젝트를 정리한다.
