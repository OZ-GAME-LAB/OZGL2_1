# StageManager 보강 검증 결과

Unity 6000.3.22f1 / JOB_KIMGUN / 2026-09-09

## 추가 디커플링 보강

- StateChanged 구독자를 개별 호출하고 오류 횟수·마지막 예외·실패 구독자 정보를 보관.
  동기 UI 예외는 다른 구독자와 게임 진행에 전파하지 않음.
- IStageSession.SettleAsync로 정산을 요청하고, 완료 기록 저장 후 IStageLobby.ReturnAsync 호출.
  기존 FinishAsync 규격은 제거. StageManager 생성자에 IStageLobby가 필수로 추가됨.
- 처치 확정과 반환 준비 콜백 분리. IPooledHeroDeathPresentation은 선택적이며 더미는 즉시 완료.
  생존 수와 미반환 목록을 따로 관리하고 종료·취소 시 연출 대기 중인 용사도 회수.
- 실제 SO/경험치 데이터 소스 연결 및 투사체 풀은 이번 변경에서 제외.

추가 검사에서 UI 오류 격리, 정산→저장→로비 순서, 단계별 실패 차단,
정산 직후 취소 시 완료 사실 보존이 통과했습니다.
Play 검사에서는 지연 연출 중 처치 집계, 조기/중복/과거 대여 완료 통지 차단,
클리어·패배·취소 시 연출 중인 용사 회수가 통과했습니다.
변경 후 JOB_KIMGUN의 실제 두 더미 SO로 30R/50R 완주·패배·취소 및 분리된 로비 요청을 재검증했습니다.
Unity Console 오류·경고는 0건입니다.

추가 검사 메뉴는 Verify Decoupled Flow / Verify Delayed Hero Return (Play)이며,
결과는 StageDecouplingVerification.LastResult / LastPlayResult에서 확인합니다.
자동 재시도·이어하기나 실제 사망 애니메이션 제작은 포함하지 않습니다.

## 변경 내용

- RoundResult / StageRunProgress / StageRunResult로 도전별 클리어·경험치·보상 상태 분리.
- 매 라운드 결과 및 보상 적용 상태를 JSON으로 저장. 실패 시 후속 진행 차단.
- 요청 식별자와 더미 지급 영수증으로 반복 지급 차단.
- 용사 GameObject 풀링, 이전 대여·중복 사망 차단, 취소 시 보상 없는 회수.
- 화면과 StageRunHost 분리. 씬 제거 후 실행 유지.
- JOB_KIMGUN 풀링 테스트 모드, 더미 프리팹·카탈로그 추가.
- StageContracts.cs 전체를 포함한 팀 공유 문서 갱신.

## 성능 측정 범위

준비된 풀에서 1,000회 대여·반환: 추가 GameObject 생성 0개, 관리 힙 할당 0바이트.
GC.GetAllocatedBytesForCurrentThread로 해당 루프 전후를 측정했습니다.
이는 전체 전투, Task 스케줄링, UI, 저장의 무할당이나 실제 팀원 유닛 성능을 보장하지 않습니다.
전체 게임의 Unity Profiler 부하 측정은 실제 유닛 연결 후 필요합니다.

## 검사 중 수정한 사항

- 디스크 저장 도입 후 기존 20초 전체 제한이 초과되어, 20초 동안 새로운 요청이 없는 경우 실패하도록 변경.
- Editor 전용 어셈블리의 초기화 검사용 컴포넌트가 복제되지 않아 Runtime 어셈블리 위치로 이동.
  UNITY_EDITOR 조건부 컴파일로 게임 빌드에서는 제외. 이동은 Unity AssetDatabase로 수행.

## 한계와 후속 연결

실제 유닛 이동·공격·부활 상태, 기물/블록/증강 지급, 계정 성장·영구 저장은 더미입니다.
실제 보상 구현은 지급 결과와 요청 키를 함께 저장해야 합니다.
준비/전투/로비의 실제 씬 로딩은 미연결이며, 이번 씬 검사는 실행 수명 검증입니다.
동시 전멸은 미확정 오류로 종료합니다. 증강 확률도 확정하지 않았습니다.
중도 이어하기와 미완료 정산 자동 복구는 추가하지 않았습니다.
테스트 진행 기록은 persistentDataPath/stage_prototype, 자동 검사 자료는 Library/StageVerification에 저장됩니다.

기존 Unity 씬 직렬화의 빈 m_Name 뒤 공백 2건은 유지했습니다. 씬을 외부 편집하지 않았습니다.
커밋·Push·병합, Notion 수정은 수행하지 않았습니다.

## 정리 오류 보강 재검증

이번 변경 파일은 PooledHero.cs, HeroPool.cs, PooledStageBattle.cs, StageRunHost.cs와 신규 CleanupFailureProbe.cs, StageCleanupVerification.cs입니다. README 및 팀 공유 문서도 갱신했습니다.

- 반환 훅에 예외 주입: 나머지 컴포넌트 초기화와 비활성화 수행, 실패 객체 재대여 차단 통과.
- 생성 초기화에 예외 주입: 반환 초기화가 성공해도 실패 객체를 폐기하는 검사 통과.
- 전투 취소 중 반환 실패: 다른 용사 전부 회수, 원래 취소 예외와 정리 오류 보존 통과.
- 사망 반환 콜백 실패: 전투 Task에서 오류 관찰, 잔여 용사 회수 통과.
- 풀 폐기 중 반환 실패: 나머지 객체 정리 및 반복 Dispose 통과.
- Host 자원 폐기 실패: 다음 자원 폐기, 실행 취소 완료, 취소 토큰 해제, 반복 ShutdownAsync 통과.
- 기존 UI 구독자 격리·정산/저장/로비 실패 경계·저장 흐름 검사 통과.
- 기존 풀 재사용·지연 사망 연출·승패/취소·씬 제거 후 수명 검사 통과.
- 준비된 풀의 1,000회 대여·반환 구간 관리 힙 할당: 0바이트.
- JOB_KIMGUN에 할당된 SO의 30R/50R 완주·중복 시작·패배·취소 재검사 통과.
- Unity 컴파일 오류 및 검사 후 Console 오류·경고 없음. 신규 스크립트 meta 누락 없음.

오류는 각 정리 단계를 모두 시도한 뒤 집계합니다. 외부 초기화 훅 자체의 성공을 보장하는 것은 아니며, 실패한 용사는 재사용하지 않습니다. 명시적 Host 종료 시 ShutdownAsync를 await해야 합니다.
